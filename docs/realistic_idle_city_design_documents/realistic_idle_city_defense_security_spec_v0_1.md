# 1. Purpose

This document defines **defense and security** for the early game of the project.

In this game, defense should not begin as a combat fantasy system. In the early slice, security is mainly about:

- avoiding bad sites
- reducing attractants and opportunities
- keeping a clean, watchable camp
- protecting sleeping people, water, food, fire, tools, and reserves
- detecting danger early
- organizing response
- limiting damage
- preventing recurring failures

The early game should therefore treat security as a **daily survival institution**, not merely a battle mechanic.

This spec is written to fit the current design stack:

- one vulnerable starter NPC
- survival-first early progression
- explicit items/processes/structures
- social legitimacy and policy-based control
- realistic settlement thresholds
- hazard-driven incidents
- compact, information-dense player control

# 2. Scope and boundaries

## 2.1 Included in this spec

This document covers:

- personal defense and emergency self-protection
- camp and hamlet physical security
- food/waste attractant discipline as security
- perimeter logic
- night security and watch systems
- outsider approach and access control
- theft / sabotage / tampering risk
- animal and predator deterrence
- fire security and emergency response security
- role authority during threats
- alarm and mobilization systems
- post-incident recovery and preventive follow-up

## 2.2 Not the main focus of this spec

This document does **not** deeply define:

- full tactical combat simulation
- warfare between polities
- large-scale raids or military campaigns
- advanced fortification engineering
- firearms, modern policing, or state justice systems

Those belong to later-era or separate documents.

## 2.3 Early-slice design stance

For the lone survivor -> tiny hamlet slice, the most realistic security priorities are usually:

1. hazard avoidance
2. camp placement
3. food/waste discipline
4. fire control
5. visibility and early warning
6. simple deterrence
7. sleeping protection
8. outsider protocol
9. controlled escalation
10. social order inside the group

Combat may happen, but **most successful early security is preventive**.

# 3. Core design principles

## 3.1 Security is broader than combat

A camp can fail because of:

- predator attraction
- spoiled or stolen reserves
- fire spread
- nighttime exposure during panic
- outsider theft
- interpersonal conflict
- tool sabotage or misplacement
- unsafe shelter layout
- poor line-of-sight
- no alarm chain

So “defense” should be treated as a combination of:

- site choice
- layout
- discipline
- monitoring
- access control
- deterrence
- response
- recovery

## 3.2 Cleanliness is security

In the early game, dirty camp behavior is not just a health problem. It is a security failure.

Food scraps, offal, fish remains, hides, grease, and waste increase attraction risk for scavengers and larger wildlife. Security therefore overlaps directly with:

- food handling
- butchering layout
- refuse disposal
- latrine siting
- carcass handling
- storage and sealing

## 3.3 Visibility matters

Good early security comes from being able to:

- see approach routes
- hear disturbance
- notice missing items
- track who is inside the core camp
- identify when fire or smoke is abnormal
- see who is on watch
- detect when animals are circling or rooting near stores

Dense concealment, clutter, and hidden approach routes should be treated as real liabilities.

## 3.4 Security is layered

The early game should use multiple thin layers rather than one fantasy wall:

- good site choice
- low attractant discipline
- physical separation of key areas
- simple perimeter cues
- noise alarms
- sleeping fire zone / lit core zone
- tools ready near risk areas
- watch rotation when justified
- role-based response rules

## 3.5 Security depends on legitimacy

NPCs should comply with difficult security rules better when:

- leadership is trusted
- rules are fair
- warnings are consistent
- burdens are shared
- monitoring is visible
- incidents are explained and remembered

If rules feel arbitrary, compliance should fall.

## 3.6 Escalation should be bounded

The realistic early model is:

- avoid
- deter
- warn
- secure people and reserves
- retreat or regroup if needed
- fight only when necessary or advantageous

The game should not reward reckless heroics as the normal solution.

# 4. Threat taxonomy

## 4.1 Environmental-security threats

These are hazards that become security problems because they threaten sleeping people, reserves, or order.

Examples:

- wildfire or grass fire approach
- ember spread from camp fire
- falling tree / branch in storms
- nighttime cold surge
- flood pulse / drainage overflow
- smoke accumulation in sleeping zones
- lightning exposure in bad terrain

## 4.2 Wildlife / predator threats

Examples:

- scavengers raiding scraps or stores
- nocturnal animals entering sleeping zone
- repeated camp approach by conditioned wildlife
- direct attack on isolated NPC
- animal harassment of future penned stock

## 4.3 Human outsider threats

Examples:

- suspicious approach
- opportunistic theft
- trespass into stores / sleeping zone
- tool or reserve tampering
- coercive demand for food or water
- scouting behavior
- retaliation after prior conflict

## 4.4 Internal social-security threats

Examples:

- theft from communal stores
- hoarding during scarcity
- refusal to stand watch
- sabotaging another NPC’s work
- panic behavior during fire or predator event
- fights over allocation, status, or leadership

## 4.5 Process and infrastructure security threats

Examples:

- unattended fire
- sparks near bedding or dry thatch
- unsecured sharp tools around sleeping area
- unstable cache collapse
- hidden spoilage in reserve stores
- broken gate or pen closure
- forgotten food at worksite
- unsecured outsiders near sensitive work areas

# 5. Security functions

Every defense/security system in the game should be understandable as one or more of these functions.

## 5.1 Anticipate

Recognize likely trouble before it starts.

Examples:

- noticing predator sign
- tracking outsider frequency near camp
- spotting rising wind before night fire use
- noticing that scraps are building up
- recognizing repeated disputes around stores

## 5.2 Deter

Reduce the chance that the threat chooses to engage.

Examples:

- lit and occupied camp core
- visible human presence
- thorn barrier at vulnerable gap
- clean food discipline
- alarm rattles near store area
- socially known sanctions for theft

## 5.3 Delay

Slow the threat enough to react.

Examples:

- simple gate
- thorn hedge
- tied door panel
- raised store platform
- lidded container
- animal-guarded approach lane later

## 5.4 Detect

Make abnormal activity obvious.

Examples:

- watch rota
- clear approach lanes
- visible store seals or markers
- noise lines / hanging rattles
- glow from hearth revealing movement
- trackable footprints in some ground conditions

## 5.5 Respond

Move the right people to the right task fast enough.

Examples:

- wake sleepers
- secure children or weak NPCs later
- move food from exposed site
- control fire line
- confront outsider at boundary instead of deep inside camp
- cluster defenders rather than trickling in one by one

## 5.6 Recover

Limit long-term damage.

Examples:

- inspect losses
- restore watch
- check injured NPCs
- repair damaged boundary
- recount stores
- adjust policies
- record incident lessons

# 6. Security maturity ladder by settlement stage

## 6.1 Stage 0 — Lone Survivor

### Security identity
A person trying not to become vulnerable at night.

### Main risks

- isolation
- sleep vulnerability
- no one to warn or assist
- limited carrying means critical items can be lost easily
- camp chosen in haste
- food scraps and smells too close to sleep
- fire misuse

### Realistic security tools

- careful site selection
- keeping the sleeping site small and controlled
- one or two tools immediately reachable from sleep
- fire placed for warmth/light but not shelter ignition risk
- stores kept separate from bed if possible
- simple deterrent line or thorn scatter at likely approaches
- noisemaker improvisation where materials allow

### What should not exist yet

- formal patrols
- permanent guards
- reliable perimeter walls
- broad weapons inventory

## 6.2 Stage 1 — Primitive Camp

### Security identity
A repeatedly occupied camp with defensible habits.

### Main changes

- stable hearth
- known approach routes
- better storage
- some waste separation
- first repeated animal or outsider patterns become visible

### New security options

- designated clean camp core
- worksite cleanup routine
- raised or hidden cache logic
- perimeter markers
- thorn barriers at easiest entry points
- simple watch task during higher risk nights
- stronger spear/club tools
- alarm objects near stores

## 6.3 Stage 2 — Permanent Camp

### Security identity
A place with reserves worth protecting and routines worth enforcing.

### Main risks

- larger stores attract both animals and people
- more structures create blind spots
- fire risk rises with more dry material and thatch
- disputes matter more because assets accumulate

### New security options

- clearer inner and outer camp zones
- formal store access rules
- locked or sealed containers later in stage
- outsider waiting point
- duty rotation for watch or fire check
- designated response tools at known points
- separate butchery/refuse zones to reduce attractant load in core camp
- structured night shutdown checklist

## 6.4 Stage 3 — Tiny Hamlet

### Security identity
A small society protecting people, reserves, norms, and future growth.

### Main risks

- multiple huts and stores
- vulnerable plots and small stock
- more outsiders, visitors, and trade-like contact
- more internal fairness disputes
- more people asleep simultaneously
- greater need for role clarity during incidents

### New security options

- visible boundary logic
- posted or culturally known norms
- stable watch rota during elevated risk
- child/weak person protection rules later if relevant
- gate or entry funnel where layout allows
- small guard / response role without becoming militarized
- storekeeper + security logging
- dispute ladder tied to governance
- community muster point

# 7. Site selection as security

## 7.1 Security-positive site traits

- good line of sight to likely approach routes
- moderate natural defensibility without trapping the camp
- ground above routine flood / drainage channels
- no overhanging dead trees over sleeping or fire area
- water close enough for access but not so close that camp sits in wet habitat or high animal traffic
- enough open space to expand while preserving visibility
- brush and timber accessible but not pressing directly against sleeping/store core

## 7.2 Security-negative site traits

- dense brush immediately around sleeping zone
- narrow funnel with no alternate escape
- camp on game trail or direct water access path used heavily by animals
- flood-prone hollow
- isolated tall tree exposure in lightning-prone storms
- stores and shelter crammed together in clutter
- no visual separation between fire, bedding, and dry fuel

## 7.3 Approach geometry

The map should track:

- obvious approach lanes
- concealed approach lanes
- night visibility arcs
- sound travel quality
- escape routes
- choke points

Security value should partly depend on whether the camp can see and manage its own approaches.

# 8. Layout security doctrine

## 8.1 Security zones

Early settlements should gradually separate into practical zones:

### Core sleeping zone
Where the most vulnerable people rest.

### Hearth / lit activity zone
Night visibility, warmth, last-resort regroup point.

### Food and reserve zone
Must be dry, monitored, and not casually entered.

### Dirty processing zone
Butchery, hide work, refuse handling, bloody or greasy tasks.

### Latrine / waste zone
Away from core camp and water.

### Reception / outsider edge zone
A place where outsiders are first seen and addressed before reaching stores or sleepers.

## 8.2 Security effects of zoning

Good zoning improves:

- detection
- cleanliness
- fire safety
- outsider control
- theft visibility
- predator attraction control
- incident containment

Bad zoning creates:

- confusion during alarms
- hidden theft
- more wildlife attraction near beds
- more ember spread into fuel and bedding
- outsider access to sensitive areas

## 8.3 Core camp rules

The core camp should prefer:

- no butchery
- no refuse piles
- no unattended food scraps
- no casual open flame inside crowded sleeping materials
- no hidden stock behind bedding
- no dense clutter blocking visibility

# 9. Food, waste, and attractant security

## 9.1 Why this is a defense issue

A camp that leaves food, scraps, grease, bones, fish remains, or scented items unsecured is advertising itself to scavengers and larger wildlife.

In many environments, that is one of the earliest and most realistic security failures.

## 9.2 Attractant classes

Track attractants separately from ordinary item ownership.

### High-attractant

- raw meat
- fish
- offal
- fat
- bloodied hides
- cooked food residues
- refuse with food remains

### Medium-attractant

- dried meat
- smoked meat
- grain and seeds
- animal feed later
- dirty cookware

### Low-attractant

- clean dry fiber
- stone
- clean wood
- clay

## 9.3 Security rules around attractants

- never leave high-attractant material in sleeping core unless no alternative exists
- bloody work should pull NPC traffic toward dirty zone
- offal should trigger disposal urgency
- store inspection should include smell / residue status
- hidden scraps should create delayed incident risk
- camp cleanliness rating should directly affect wildlife incident chance

## 9.4 Special reserve protection

Seed stock, dried food, and preserved food are not just nutrition. They are strategic security assets.

Losing them to moisture, pests, theft, or scavengers should count as a severe security failure.

# 10. Fire security

## 10.1 Fire as both protector and threat

Fire gives:

- light
- warmth
- some predator deterrence
- regroup point
- alarm visibility

But it also creates:

- burn risk
- structure ignition risk
- smoke burden
- ember spread
- nighttime panic
- carbon monoxide risk in enclosed or poorly ventilated spaces

## 10.2 Fire security doctrine

Early camps should treat fire as a controlled security asset.

Key rules:

- keep flame where it can be observed
- maintain clear area around open flame
- separate dry bedding/thatch/fuel stock from routine sparks
- assign fire-check responsibility on high-risk nights
- extinguish or reduce unsafe fires before sleep when conditions demand it

## 10.3 Fire states to track

- contained and watched
- contained but unattended
- smoky / poorly drafted
- wind-exposed
- ember-casting
- shelter-adjacent risk
- near stored fuel risk

## 10.4 Fire incident types

- bedding ignition
- thatch ember ignition
- fuel pile catch
- panic scattering of tools/embers
- smoke saturation in shelter
- nighttime fire loss reducing morale and safety

# 11. Personal defense and emergency tools

## 11.1 Early realistic personal defense tools

- wooden club
- sharpened spear
- firebrand / torch for deterrence in some cases
- stone knife / cutting tool as emergency weapon but poor primary defense tool
- staff / walking stick with defensive use

## 11.2 Tool realism stance

The early game should avoid turning every tool into a combat class.

Most objects should be modeled by:

- reach
- handling speed
- intimidation value
- lethality
- injury risk to user
- usefulness in tight spaces
- nighttime usability
- maintenance state

## 11.3 Ready-state rules

A camp is more secure when:

- at least one tool is near each sleeper or sleeping cluster
- one response tool is near main approach / gate area
- fire response tools are near hearth and fuel stock
- watch NPCs do not begin shift empty-handed

# 12. Perimeter systems

## 12.1 What early perimeters really are

In the early slice, a perimeter is usually not a full wall.

It is often a combination of:

- visible edge marking
- brush clearing
- thorn or stake deterrence at easy approaches
- simple gate path or one obvious entry lane
- alarm objects
- lighting from hearth or torch positions
- known “do not cross” norms

## 12.2 Perimeter functions

- indicate territory
- slow movement
- make intrusion visible/noisy
- channel movement to expected entry points
- help keep children/weak NPCs or small animals inside later
- reduce surprise at night

## 12.3 Perimeter maturity ladder

### Lone survivor
- almost none
- maybe thorn scatter or simple warning line

### Primitive camp
- marked edge around sleeping/store core
- simple noisy trip features where feasible

### Permanent camp
- partial brush/thorn barrier
- repeated maintained approach lane
- simple gate point or entry side

### Tiny hamlet
- boundary logic around inhabited core
- one or more preferred entry paths
- fenced or thorn-protected sensitive areas
- separate pen protection for stock later in slice

## 12.4 Bad perimeter patterns

- barrier that creates blind spots
- barrier with too many holes to monitor
- boundary that traps people from water or escape route
- attractive hidden corners for theft or concealment

# 13. Detection, watch, and alerting

## 13.1 Detection channels

The game should support multiple believable detection channels:

- direct line-of-sight
- sound
- animal agitation
- missing item or broken seal check
- smoke/fire visibility
- smell / contamination clues
- track or sign observation by skilled NPCs

## 13.2 Night watch realism

Night watch should not exist by default from day one. It becomes rational when:

- reserves become worth protecting
- outsider traffic increases
- predator pressure is recurrent
- fire risk is high
- group size allows rotation without crippling next-day labor

## 13.3 Watch costs

Watch is never free.

Costs include:

- sleep loss
- next-day fatigue
- morale burden
- fairness complaints if assignments feel uneven
- false alarms
- social distrust if watch authority is abused

## 13.4 Watch formats

### Solo alert rest
Lone survivor sleeps lightly / wakes often. High fatigue cost.

### Ad hoc watch
One NPC stays semi-alert during a risky window.

### Rotating watch
Several NPCs take short shifts.

### Fire-watch
Watch focused mainly on embers and shelter safety.

### Perimeter-watch
Watch focused on approach lanes and outsider/wildlife signs.

## 13.5 Alert systems

Possible early alert devices and methods:

- shouting
- striking wood / stone
- hanging bone / shell / pottery rattle lines
- dogs later if available through social/agricultural routes
- visible torch signal
- horn/whistle later if made

## 13.6 Alarm quality factors

- audibility
- distinctness from ordinary work noise
- false alarm rate
- nighttime effectiveness
- wake-up speed
- weather sensitivity

# 14. Outsider approach and access control

## 14.1 Early outsider categories

- neutral wanderer
- needy traveler
- curious observer
- trader/prospective exchanger later
- possible thief / scout
- desperate intruder
- hostile outsider

## 14.2 Access control doctrine

The early settlement should not treat every outsider as an enemy, but it also should not let unknown people walk directly into reserves or sleeping areas.

Core logic:

- first contact near edge, not deep in core
- one or more NPCs respond, not scattered individuals
- sensitive stores remain out of casual access
- player policy can define generosity, suspicion, and escort strictness

## 14.3 Access zones

### Public edge
The place an outsider may stand or wait.

### Escorted service zone
Where water, aid, or trade contact may occur.

### Restricted zone
Stores, seed reserve, sleeping area, critical tools, vulnerable persons.

## 14.4 Outsider protocols

Examples:

- call-and-approach expectation
- surrender of weapon access before inner entry if policy strictness allows
- escort requirement
- supervised water or meal aid
- no overnight stay inside reserve core unless accepted/approved
- observation period for guests

## 14.5 Security effects of generosity

Generosity should have both upside and risk.

Upside:

- improved reputation
- recruitment chance
- social network value
- future aid reciprocity

Risk:

- reserve loss
- reconnaissance by strangers
- illness introduction
- norm conflict
- internal resentment during scarcity

# 15. Theft, sabotage, and tampering

## 15.1 Early realistic property risks

The earliest property crimes in this game should usually be small and practical:

- food taken from cache
- tool hidden or borrowed without return
- seed stock eaten or traded improperly
- rope/cordage cut or repurposed
- water container contaminated or misplaced
- animal pen latch left open later

## 15.2 Conditions that raise theft risk

- scarcity
- unclear ownership rules
- weak store records
- hidden resentment
- outsider access to stores
- low legitimacy of rationing
- no monitoring
- cluttered camp with many blind spots

## 15.3 Tamper markers

The game should allow stores to have visible integrity states:

- sealed / counted
- disturbed
- partly missing
- contaminated
- unverified

## 15.4 Social handling

Security should connect to governance rather than instant violence.

Useful ladders:

- question / explain
- warning
- restitution labor
- reduced store access
- monitoring increase
- separation / escort requirement
- exclusion for repeated severe breach

# 16. Predator and wildlife security

## 16.1 Wildlife-security stance

Most wildlife conflict should arise from:

- attractants
- bad siting
- repeated habituation
- poor visibility
- unsecured food/waste

The game should therefore reward prevention more than dramatic animal fights.

## 16.2 Wildlife pressure variables

- local habitat type
- season
- drought / scarcity pressure
- carcass and offal presence
- fish processing frequency
- camp cleanliness score
- proximity to water / game trail
- prior incidents at site

## 16.3 Deterrence ladder

- remove attractants
- relocate dirty work away from core
- increase visibility and noise
- reinforce store security
- use fire/light/human grouping appropriately
- simple active harassment of small scavengers
- coordinated defense only when needed

## 16.4 Repeated-conditioning rule

If a camp repeatedly leaves food available, wildlife should become bolder over time.

This is important because it makes security historical, not only situational.

# 17. Security for vulnerable people and assets

## 17.1 High-value assets

- potable water
- seed reserve
- preserved food reserve
- critical tools
- fire source / ember continuity in cold conditions
- knowledge records later
- domesticated animals later

## 17.2 High-vulnerability NPC groups

In the early slice, vulnerability is state-based more than class-based:

- sleeping NPCs
- injured NPCs
- sick NPCs
- exhausted NPCs
- heavily burdened haulers
- children later if present

## 17.3 Protection priorities during incident

Recommended order in most early incidents:

1. protect life
2. prevent spread / escalation
3. secure water and fire safety
4. secure reserves if possible
5. recover tools and livestock later if time allows
6. investigate cause after immediate stabilization

# 18. Role authority and emergency command

## 18.1 Normal vs emergency authority

Normal authority can remain policy-based and decentralized.

During acute incidents, a temporary emergency command mode is realistic and useful.

## 18.2 Temporary emergency roles

- incident lead
- fire response lead
- watch lead
- outsider contact lead
- wounded care lead
- reserve securement lead

One NPC can hold several in tiny populations.

## 18.3 Emergency role triggers

- active fire spread
- predator inside core camp
- violent dispute
- unknown outsider breach at night
- flood or storm evacuation
- missing person after dark

## 18.4 Command limits

Emergency authority should expire once immediate danger ends.

Otherwise it creates resentment, abuse potential, and legitimacy loss.

# 19. Security and morale / legitimacy

## 19.1 Good security can improve morale when it feels:

- competent
- fair
- calm
- visible
- effective
- not overly burdensome

## 19.2 Bad security lowers morale when it feels:

- arbitrary
- paranoid
- unequal
- exhausting
- humiliating
- ineffective despite effort

## 19.3 Social variables linked to compliance

- trust in leader
- confidence in watch competence
- recent incident memory
- perceived fairness of watch burden
- belief that stores are protected honestly
- outsider empathy vs fear stance

# 20. Security policies the player can set

## 20.1 Standing policies

Examples:

- food-storage strictness
- night-watch threshold
- outsider screening strictness
- reserve access restrictions
- curfew / night movement policy
- fire shutdown policy
- tool placement policy
- animal carcass/offal disposal urgency
- escort requirement for non-members

## 20.2 Conditional policies

Examples:

- high predator pressure mode
- scarcity lockdown mode
- storm/night emergency mode
- active outsider caution mode
- elevated fire danger mode

## 20.3 Security doctrine presets

### Open but careful
Favors generosity, light access control, high monitoring.

### Guarded
Moderate controls, escorted outsiders, stronger reserve protection.

### Hard scarcity
Strict reserve control, reduced outsider aid, more complaints but fewer losses.

### Fire season / dry wind
Tighter flame rules, more fire-watch, greater fuel separation.

# 21. Security linked to other systems

## 21.1 Health
Security failures can produce:

- injuries
- smoke inhalation
- contamination
- sleep loss
- panic fatigue
- infection after violence or accident

## 21.2 Allocation
Security affects who can access:

- seed
- preserved food
- emergency water
- medicine/care items later
- high-value tools

## 21.3 Knowledge
Repeated incidents should generate knowledge such as:

- “do not butcher near sleeping zone”
- “this cache type fails in heavy rain”
- “this approach lane is bad at night”
- “thorn barrier works against small intruders but not larger animals”

## 21.4 Governance
Security norms need:

- clear boundaries
- monitoring
- consequences
- appeal/conflict handling

## 21.5 World generation
Map/site traits should shape:

- predator pressure
- outsider traffic
- line of sight
- flood/fire vulnerability
- escape options

# 22. Incident families to support

## 22.1 Lone-survivor incidents

- night animal approach
- hidden scrap attracts scavenger
- fire spreads toward bedding
- spear lost outside immediate reach
- sleep interrupted repeatedly by sound/fear

## 22.2 Primitive-camp incidents

- cache disturbed
- stranger seen near water point
- repeated nocturnal scavenging
- conflict over watch burden
- accidental cut or burn while responding at night

## 22.3 Permanent-camp incidents

- offal pit too near core increases wildlife pressure
- outsider steals preserved food bundle
- ember catches dry roof edge
- store seal broken
- guard/watcher falls asleep from fatigue

## 22.4 Tiny-hamlet incidents

- fight over ration theft accusation
- guest violates restricted zone
- small-stock pen breach later in slice
- organized reserve recount after discrepancy
- false alarm reduces trust in watch system
- repeat trespass prompts stronger access control

# 23. First-playable minimum defense/security slice

For the first fully playable early-game version, the minimum viable security layer should include:

## 23.1 Threats

- wildlife attraction from dirty camp
- night exposure vulnerability
- fire spread risk
- occasional outsider approach
- internal theft/tamper possibility after more than one NPC exists

## 23.2 Objects and structures

- spear/club tool tags
- hearth fire states
- cache security states
- thorn barrier / simple stake deterrent
- alarm rattle line
- marked camp core

## 23.3 Policies

- food/waste strictness
- outsider approach rule
- watch enabled / disabled threshold
- reserve access rule
- night fire rule

## 23.4 NPC behaviors

- wake on alarm
- respond to outsider at edge if able
- avoid storing raw meat in sleeping core when knowledge/policy allows
- prioritize extinguish / contain when fire threatens shelter
- choose grouped response over solo heroic chase when odds are bad

## 23.5 Metrics

- camp cleanliness security score
- visibility / line-of-sight score
- reserve exposure score
- watch burden / fatigue burden
- incident recurrence memory
- outsider trust level

# 25. Design recommendations and cautions

## 25.1 Strong recommendation

Treat early security as a **camp discipline system** first and a **combat system** second.

That means the player succeeds mainly by:

- choosing good sites
- keeping the camp clean
- separating clean and dirty zones
- protecting reserves
- controlling fire
- using visibility and access control
- keeping fair watch burdens
- responding coherently

## 25.2 Important caution

Do not let “security” become free static bonuses from walls or guard posts in the early slice.

It should remain an interaction between:

- terrain
- cleanliness
- storage
- layout
- sleep/fatigue
- policy
- legitimacy
- vigilance

## 25.3 Expansion path later

Later eras can deepen this into:

- stock pen defense
- escort routes
- watchtowers
- road security
- storehouse locks and seals
- formal guard roles
- armories
- anti-bandit patrols
- legal enforcement institutions
- urban fire brigades and night watch systems
